# 定时回顾计划保存性能

## 原因与改动

保存计划不调用大模型。旧路径先执行通用 `persist()`，其中包含理解任务核对、回顾有效性检查、知识账本整理和 SQLite 索引同步；随后 `RecallAppModel.refresh()` 又会同步提醒、重建主题投影、核验通知、检查补生成并启动后台维护。记录越多，用户等待越长。截图未开启“生成后发送系统通知”，不涉及等待通知授权。

计划保存与删除改用原子状态写入，保持原有 JSON 格式和失败回滚；不运行内容整理或索引维护。相同的已保存计划不重复写盘。应用只更新计划列表并确保原有定时检查器启动，不等待全页面刷新，不立即生成回顾。勾选通知时仍按原有流程确认系统权限。

保存按钮立即显示小型进度与“保存中”，防止重复提交，保存期间锁定表单。成功才关闭弹窗，失败保留输入、原计划和重试入口；保存、暂停与删除均保持原有定时执行语义。

## 验证

新增 6,351 条合成记录的保存耗时与数据不变检查：原始记录、已存回顾、账本、队列和索引维护状态不被计划保存改写。另覆盖时区/下次执行时间、重启、暂停、删除、相同计划不写盘、失败回滚与重试。

原生入口验证确保计划保存后页面数据可见，不触发主题重建或即时回顾；失败会清除忙碌状态并保留原计划。增加计划编辑与保存中的原生预览。所有场景使用合成数据，不采集屏幕、不调用模型、不申请真实通知权限。
