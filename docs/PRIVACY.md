# Recall 隐私设计

Recall 的产品前提是：个人屏幕内容属于高敏感数据。应用只应在用户理解、选择并可随时撤销的前提下采集和处理这些内容。本文件描述当前 MVP 的数据边界与实现约束，未来任何改变默认采集范围或外发范围的 PR 都必须同步更新此文档和应用内说明。

## 默认行为

Recall 默认启用的事件模板仅包括“手动记录此刻”“当前窗口工作节点”“待办或承诺创建”和“定时个人回顾”。其中，只有用户明确发起的记录动作可能触发截图；每日回顾只汇总既有数据，不会在后台新增截图。Enter 键触发记录是默认关闭的独立规则：只有用户在“记录事件”中显式启用并授予键盘输入监控权限后才会生效；它不拦截原按键、仅在 Recall 不在前台时监听、支持暂停且带有去重冷却。连续截屏、定时截屏、音频录制与消息内容自动采集均不是默认功能。

| 数据类型 | 默认处理位置 | 默认是否外发 | 用户控制 |
|---|---|---:|---|
| 截图 | 本机 `Application Support/Recall/Screenshots` | 否 | 可暂停、关闭原图保存、按记录删除或全部清除。 |
| OCR 文本与摘要 | 本机状态文件 | 否 | 可按记录删除；通过事件规则设置保留天数。 |
| 应用与窗口元数据 | 本机状态文件 | 否 | 可通过 Bundle ID 排除应用。 |
| 对话记录 | 本机状态文件 | 否 | 删除全部本地记忆时一并移除。 |
| 云端模型 API Key | 本机 `Application Support/Recall/recall-state.json` | 否 | 根据项目所有者要求作为普通文本保存；可在模型设置中编辑或删除，不写入日志或 Git 仓库。 |
| 云端模型上下文 | 用户配置的 OpenAI/Anthropic 兼容服务 | 仅在用户明确开启云端模式并提问时 | 仅发送当前问题、检索文本片段、滚动摘要和最近消息窗口；OCR、摘要和历史消息均在发送前执行基础脱敏。 |

## 采集前控制

屏幕采集前，Recall 会检查三件事：用户是否已暂停采集、当前应用是否位于排除列表、系统是否已授予屏幕录制权限。任一项不满足时，应用中止本次记录并提示原因。启用 Enter 键触发记录还需要 macOS 键盘输入监控权限；未获得该权限时不会读取键盘事件或触发记录。默认排除密码相关、Keychain 和消息类应用；用户可在设置中扩展 Bundle ID 排除列表。

应用不会试图绕过 macOS 权限。在首次实际需要截图时，用户需要在系统设置中允许屏幕与系统音频录制。用户可以随时在系统设置或 Recall 的菜单栏入口暂停此能力。

## 处理与留存

OCR 通过 macOS Vision 在设备上运行。文本会经过基础模式脱敏；当前 MVP 覆盖常见邮箱、长数字卡号和“密码/验证码”形式的行级内容。该规则是额外保护而非安全承诺：用户应把高敏感应用加入排除列表，且项目后续应引入更丰富的本地分类和屏幕区域排除机制。

事件规则分别控制原始截图保留天数和 OCR 文本保留天数。删除一条记录会同时删除关联截图；“删除全部本地记忆”会遍历并删除现有记录与截图。应用不提供不可撤销的云端备份或隐藏副本。

## 会话与来源

本地模式下，会话通过关键词检索既有记忆并生成带引用的摘要，不进行网络请求。云端模式不是默认状态。启用后，用户可选择兼容 OpenAI 或兼容 Anthropic 的协议，并编辑服务地址、模型名称和本机普通文本 API Key；应用不访问 Keychain，因此不会产生系统钥匙串授权窗口。Recall 会将长会话组织为“滚动摘要 + 最近消息窗口 + 检索证据”：早期消息仅保留在本地展示，同时压缩为摘要；发送云端前，OCR、摘要和最近消息均会经过基础文本脱敏，图片路径不会发送。系统提示要求模型只根据输入记忆回答并标注引用，但模型输出仍可能出错，用户应通过来源记录验证重要内容。

## 提醒

Recall 不会因为模型或规则推断就直接发送提醒。它只会创建候选，显示候选的来源记录、置信度与说明；用户点击创建后，应用才会请求通知权限和安排本地通知。应用不代表用户发送消息、创建日历事件、修改文件或执行其他外部操作。

## 安全报告

请不要在公开 issue 中披露可被利用的隐私或安全漏洞。请遵循仓库根目录的 [SECURITY.md](../SECURITY.md) 提交报告。
