# Recall 统一记忆架构

目标：记录能形成可更新、有范围、可纠错、可撤回的记忆，让用户重新进入一件事时能承接进度，并找到有依据的历史经验。

## 数据与来源

- `CaptureRecord` 保存原始证据；`memoryDirective` 仅由用户明确输入或编辑产生，OCR 不填入此字段。
- `MemoryEvidence` 保存来源 ID、片段序号、原文、归属、来源版本、记录时间及明确的发生时间。
- `MemoryClaim` 保存主体、完整内容、类别、适用范围、当前有效状态、版本替代、依赖和有效期。本人观察与他人请求分开；请求仅形成待确认候选。
- `MemoryEntity` 保存主题或人物及用户提供的别名。别名帮助检索，不自动合并两个不同身份。
- `MemoryDependency` 关联事实、来源与派生输出；总结、周回顾和回答同时保存实际输入的约定来源。
- 停用规则保存不可读内容的稳定标识，避免删除原文后在规则中残留文本。

## 写入与整理

明确的“记住”当场保存，直接返回执行结果。工作、生活、学习、主题和全局作用域独立，本次会话优先级最高。同范围的新版本替代旧版本；不同范围的约定并存。明确约定及更正是用户输入，不能从屏幕资料自动提升而来。

普通采集先保存原始证据。后台按来源版本检查点整理，有变化才重新构建投影；原文分句、角色归属、多事项拆分、重复去重共用 `RecordedText` 与 `MatterEvidence`。后台整理独立于每日总结，每五分钟检查，启动、激活、唤醒时检查；可暂停并手动触发。关闭自动整理不阻止删除、到期失效或用户明确的记忆命令。

事实状态包括有效、线索、冲突、被替代、停用和过期。重复截图不增加独立确认次数。相反偏好作为冲突保存，用户更正后采用明确版本。记录缺失不推断停滞；浏览资料不推断掌握、收益或习惯。

## 共用的读取路径

记忆脉络和周回顾读取事实投影，缺少可用投影时从同一原文解析器恢复。每日总结将同一事实转为片段、项目最新状态和简报；旧工作片段只提供主题线索，不能绕过原文归属验证。

问一问先识别时间和问题意图，定位主题/人物/状态，再按来源和别名做第二次有预算的补查。跨日问题先保证日期覆盖。当前状态问题保留早期与最新变化，历史方法问题优先读取有结果的经验。证据列表与每条文本长度受现有上下文预算约束。

适用约定单独放入有预算的上下文，只调整表达与组织；人物事实按问题检索。所有来源须仍存在且允许用于问一问，应用排除项作用于原文和派生内容。模型回答的引用映射回原始来源，生成期间发生更正、删除或约定变化时拒绝提交旧结果。

## 遗忘与保留

原始截图、文本按照事件保留规则清理。明确约定可独立保留必要文字，关闭独立保留后仍按文本期限清理。已过期、被替代和停用的约定不享有长期保留；清空当前会话使本次会话约定失效。

“停用”保留可查的原文与历史版本，并停止使用。忘记关联记录会走现有最近删除事务，撤回所有使用相关来源的派生内容；七天内可恢复，到期禁止恢复。项目正文不能仅移除来源 ID 后原样保留。源内容变化后重新核对，防止旧推断重新出现。

到期截图清理使用持久化队列，成功后移除队列项，失败记日志并重试；应用关闭期间不运行，下次启动补清理。SQLite 是可重建投影，JSON 继续作为持久化状态；全文索引在事务中增量更新，失败回退内存检索并重建，不把派生索引故障当成原始状态保存失败。

## 页面

“记忆脉络”新增“记忆与约定”，包含约定与偏好、人物与关系、历史经验；支持搜索、分页、查看旧版本、原始来源、更正、停用、忘记、别名和有效期。事实本身不显示专业概率分数。后台设置与保留策略放在页面底部，避免占据主要阅读区。

## 验收

合成数据覆盖九组场景：

1. 同屏多个事项、角色隔离、引用材料排除、重复截图日期与稳定 ID。
2. 即时约定、新旧版本、全局/工作/生活/本次会话隔离、矛盾偏好和人物事实。
3. 别名补查、原始引用映射、七天覆盖和被排除来源隔离。
4. 暂停、手动整理、重启续接及暂停期间的删除撤回。
5. 原文到期、明确约定最小保留、截图失败队列及关闭独立保留。
6. 派生依赖、更正、停用、原文反向召回阻断和彻底忘记。
7. 每日总结、脉络与问一问对事实归属和最新状态的一致性。
8. 有明确结果才能形成经验，完成依据撤回后经验失效。
9. SQLite 增量更新、旧全文清除、未变化行和删除同步。

CI 在 macOS 执行完整编译与集成验证。真实窗口布局、系统通知及真实模型写作效果仍需在完整 macOS 图形环境实测。
