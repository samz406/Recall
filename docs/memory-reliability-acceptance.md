# Recall 基础可靠性验收

基线：main `ba001a3c53babcbac69a2af255f7356c40fce781`。范围：原始记录保存、回答依据、用户数据控制和记录/查询异常恢复。本次不改打包分发，不新增持续采集、云同步或默认外发。

## 行为与实现

| 要求 | 实现 | 用户看到的变化 |
| --- | --- | --- |
| 写入可确认 | 主档案仍原子写入；失败恢复内存状态；文件锁与内容摘要阻止应用/CLI 覆盖其他写入者的新记录 | 成功才提示保存；冲突提示重新打开，不静默覆盖 |
| 损坏可恢复 | 最新状态镜像以 SHA-256 文件名校验；拒绝损坏/未来版本/带旧明文 Key 的恢复点；恢复前隔离损坏原件 | 启动失败进入恢复页面，可选择已校验的备份、打开数据文件夹或重试；没有空白档案替代 |
| 回答有依据 | 草稿增加一次有界的独立模型核验；每条结论对应逐字引用，再做本地引用、身份、状态、条件和数字检查 | 未核对的草稿不显示；保留合格结论，只去掉问题条目；核验失败展示原文摘录 |
| 未找到不乱说 | 空范围直接本地返回；检索增加索引不可用时的本地文字匹配回退 | 明确说未找到可用记录，不把它说成事情没发生 |
| 权限可撤回 | 每次规划、工具后续请求和核验前重查云端许可、来源、更正、身份和会话状态 | 关闭云端、删除或更正来源后，不继续发送下一轮文本，也不保存过期回答 |
| 重要文字可长期保留 | 记录详情中的长期保留开关，兼容旧档案 | 文字不再到期，截图仍按原期限清理；取消后恢复普通期限；手动删除优先 |
| 删除可完成 | 先持久化删除意图和文件清理队列，再删除字节；失败保留队列，启动、回到应用和定时重试 | 设置显示待清理数量并可重试；不把文件残留当作全部成功 |
| 删除不从备份复活 | 写入前撤销旧镜像，写入后只保留当前镜像；清理应用管理的 CLI 备份和损坏档案 | 永久删除后，不提供旧数据恢复点；失败清理有可见状态 |

## 自动验证范围

新增 7 组离线合成检查：坏档案/校验失败/未来版本恢复、永久删除后恢复不复活、无权限删除与重启后重试、两个写入者冲突与内存回滚、长期文字和截图分开到期、错误角色/完成状态/日期/引用以及逐项保留、实际 Ask 的错误草稿/坏核验/混合坏条目/无证据/运行中撤权、断网与取消核验。

原生入口检查覆盖坏档案进入恢复页面、详情保留开关和备份重试；新增恢复页面、保存与清理卡片、记录详情的宽/窄/深色/英文渲染。现有计划保存、首屏加载、时间线、提醒等回归保留。

所有数据均为合成数据，验证脚本不调用真实模型、真实截图、钥匙串或系统通知。

## 边界

- 核验是降低事实错误的保障，不是数学上的零幻觉证明。原始 OCR 本身仍可能错误，用户可核对原文并更正；模型真实质量不能由离线替身推算正确率。
- 云端 Ask 增加一次核验请求，输入最多 24 条、合计约 24,000 字符，输出最多 4,000 token；超出覆盖会说明范围。可取消；失败回退原文。没有为了核验重新扫描全库或扩大用户授权范围。
- 备份只有最新状态镜像，保存文字与关联信息，不复制截图、不提供版本历史；异常录制遗留的无主截图会在 15 分钟保护期后纳入清理，避免误删仍在 OCR 中的截图。同一磁盘损坏、用户自行复制的文件、Time Machine、导出的文件或已提交给模型服务的文本不在本地清理保证内。
- 保留原有默认文字 90 天、截图 7 天，不擅自改成永久保存。长期保留开关不能找回此前已经到期清理的内容。
- 主档案与镜像各需一次本地写入。镜像失败会标为待完成并重试，不能把这次改动说成无额外 I/O 成本或等同跨设备灾备。
- 跨进程冲突采用安全拒绝，不自动合并不同写入者的内容。真实权限、屏幕/OCR、真实模型和长期使用仍需 Mac 实机验收。
