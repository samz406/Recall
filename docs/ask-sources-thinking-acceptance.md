# 问一问：来源展开性能与思考状态

## 修改范围

用户点击“另有 450 条来源”时，原实现同步构建全部原生菜单项，并逐条运行 `CapturePresentation`。该类型会多次对完整 OCR 做句子排序、摘要和标签解析，虽然菜单实际只需要一个标题。消息卡片还以 `captures.filter { citations.contains(id) }` 重复匹配引用，复杂度随记录数和引用数一起增长。

本次实现：

- 来源改为独立弹层，每页最多 20 条，支持标题/应用搜索、上一页、下一页；全部引用都可浏览，没有通过截掉来源来提速。
- 使用按 ID 建立的索引和引用匹配缓存，只有记录、更正或来源权限变化时失效；无关聊天更新不重建。
- 弹层首次打开不解析完整 OCR、生成摘要、读图或调用模型。只在后台准备当前页的轻量标题/应用/时间，搜索有 150 ms 防抖，过时任务取消并拒绝回写。
- 点击来源时重新按当前 ID 取记录。删除、更正和来源排除后，旧索引、旧页面或旧点击不能打开已经不可用的记录。
- 去掉检索状态与逐字显示旁的“停止”按钮。检索/整理回答后显示五段绿色波形；输入框继续呈现不可发送的忙碌状态。按 Esc 可取消，输入法组词和 `/` 命令菜单优先处理自身 Esc。
- 波形只刷新 25×16 的 Canvas，20 fps；不修改聊天模型状态，不带动整段回答与来源列表重绘。系统开启“减少动态效果”时显示静态形态。

来源标题只是列表预览；完整原始记录、图片、引用和回答正文没有被重写。

## 验证

本地为 Linux，无 Swift。已进行 `git diff --check` 和静态检查；Swift 构建及原生验证使用 macOS CI，结果待填。

新增合成回归覆盖：引用顺序/去重/缺失、452 条来源完整翻页、末页与空页、跨页搜索、超长标题上限、6,351 条记录索引、后台取消；原生回归覆盖缓存复用、同 ID 更正、删除和来源排除、波形、来源弹层首帧、Esc 与输入法。

性能数据来自合成场景，只描述对应 CI 运行，不能当作用户 Mac 的 p95 打开时间。系统权限、真实键盘焦点组合和真实 Mac 上的主观流畅度仍需人工复验。

## 样式预览

按用户指定截图制作了局部编辑预览：只去掉消息旁停止按钮和红色标记，将省略号替换为绿色五段波形，保持原有深色与绿色布局。预览采用图像生成；实际应用使用原生 SwiftUI 动画，没有把截图当作界面资源。截图和用户聊天原文未提交到仓库。
