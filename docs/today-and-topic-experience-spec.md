# 「今天 · 接着干」与「记忆 · 主题详情」改动说明

日期：2026-11-28  
范围：`TodayWorkspaceView`、`MatterWorkspaceView`、`LocalBriefing`、`TopicReading`、`TopicRegistry`

---

## 1. 核心目标：从「陈列记录」转向「十秒恢复现场」

Recall 最核心的高频场景，是多项目并行或工作被打断后重拾现场的那一刻：**一件事隔了一两天，重新接手前不用再翻聊天、找提交记录、回忆上次停在哪，十秒内看清现状并顺手往下推。**

此前两个界面的共同问题是都在回答「这里存了哪些记录」，把最费脑子的判断留给了用户：

- **打开应用看「今天」时**，用户真正要问的是：**「我现在该先做哪一件？哪些今天不用管？」**
- **点开一件事看「主题」时**，用户真正要问的是：**「最后确认它停在哪？还差什么？我马上能做什么？」**

本次改动综合两轮产品与交互评审意见，在不违背 Recall 三条不变式（**用户明确触发、敏感数据最小化、结果可删除和追溯**）的前提下，重构这两个界面的信息优先级、表达方式与操作闭环。

## 2. 关键设计取舍（融合两轮评审结论）

在合并两份设计意见时，保留双方的核心洞察，并对存在落地冲突的细节做了明确取舍：

| 设计点 | 最终方案 | 取舍原因 |
|---|---|---|
| **首页首屏结构** | **置顶展开 1 件焦点 + 下方紧凑待续队列**（不采用“只显示 1 件 + 换一件”，也不拆成 5 个碎标题） | 多项目并行需要 3 秒扫视全局的掌控感；“换一件”在算法未猜中时会产生盲盒焦虑，而 3～5 件事拆成 5 个分组标题会导致标题比内容还多。 |
| **完成动作确认** | **点击立即生效 + 底部 5 秒「撤销」提示条**（不弹二次确认框） | 原始记录完整保留且可随时撤销，属于非破坏性高频操作；每次勾选完成都弹窗确认会严重打断收尾手感。 |
| **推不动的卡点** | **补齐「今天先放下（搁置）」动作** | 若置顶规则把「卡住了」排在前面、又没有「先放下」出口，一件等外部排期一周的事会连续七天霸占榜首。 |
| **外部链接与主按钮** | **按本地已有证据动态降级**：有已保存 `pageURL` 显示「打开原网页」；仅有编号/哈希文本提供一键复制与「看上次记录」；待核对项显示「记下结果」 | Recall 默认关闭记录浏览器网址（`recordPageAddress = false`），且终端/聊天截图只有纯文本，不能让模型猜测或拼接外部链接。 |
| **「还差什么 / 下一步」** | **有据才写，无据留白** | 只展示用户本人留下的话，或记录原文明确写出的未闭环项；绝不让模型为凑齐字段编造“待后续观察复盘”之类的套话。 |
| **历史记录折叠** | **按信息密度自适应**：已有跨日小结或记录 `> 3` 条时默认折叠更早记录；无小结且记录 `≤ 3` 条时直接展示紧凑脉络 | 只有两条记录且无小结时，第一条只是单日切片，强行折叠第二条前因会让用户每次点开都多点一次展开。 |

## 3. 全站统一“人话”词表

消除此前列表、详情头、每日回顾与右键菜单各用一套术语的割裂感，全局收敛为同一套直白用词：

| 概念 | 原有多套混用词 | 统一后用词 |
|---|---|---|
| **进行状态** | 进行中 / 正在推进 | **推进中** |
| **待办状态** | 待处理 / 明确待办 | **还没做** |
| **阻塞状态** | 受阻 / 遇到阻碍 | **卡住了** |
| **搁置状态** | 搁置 / 暂停跟进 | **先放下**（列表分组称 **已搁置**） |
| **完成状态** | 已完成 / 记录为已完成 | **已做完** |
| **新增进展动作** | 补充记录 / 补充进展 | **记下进展** |
| **结项动作** | 标记完成 | **做完了** |
| **低频管理菜单** | 无名图标 `⋯` | **整理** |

## 4. 界面一：「今天 · 接着干」改动说明

### 4.1 现状问题

1. **排序反转**：原逻辑先按日期倒序、同日内才按状态排序（`LocalBriefing.openMatters`），导致前天「卡住了」的要紧事被昨天顺手推进的普通事压在后面。
2. **职责混杂与重复**：「昨天还没有回顾」（整理工作）排在待办最前面；「等别人」（`owedToMe`）既塞进「接着干」，又在下方的「往来承诺」卡片重复出现，连副标题也重复统计承诺数量。
3. **语义混淆与只读死胡同**：实质已闭环的事项、测试时偶然看到的界面报错现象与真正待继续的工作混在一起，五行长相完全一致，正文被硬截断，且不点进弹窗就无法完成或搁置。

### 4.2 改动方案：「先做一件，其余按轻重看」

#### （1）重排优先级，剥离非动手项（宁缺毋滥）
- **严格的行动优先级排序**（不再让日期压过紧急度）：
  1. **本人明确留下的下一步**（「给下次的自己留一句」）
  2. **已到期 / 今天到期的提醒**
  3. **卡住了**（`blocked`）
  4. **还没做**（`pending`）
  5. **推进中**（`inProgress` / `progressed`）
  - 同一优先级内，再按最近更新时间倒序排列。
- **过滤伪待办**：每日回顾中已完成且未留明确后续动作的条目归入完成历史；缺少本人跟进意图的单纯观察现象留在主题记录内，不主动推上首页凑数。若当天只有 1 件值得继续的事，就只展示 1 件。
- **职责剥离**：
  - **「等结果 / 等别人」** 移出动手列表，放入下方独立轻量区（标注最后确认日期，支持一键转为「我来跟进 / 设提醒」）。
  - **「缺一天回顾」** 沉到底部作为单行整理提示（「昨天还没有回顾 · [生成回顾]」），不与待办混排。
  - **副标题去重**：改为简洁说明当前待处理概况（如「先看最上面这一件，其余 3 件按轻重排列」），不再重复播报下方已有的「往来承诺」数量。

#### （2）首屏置顶焦点卡 + 紧凑队列
- **最上面单独展开第一件事**：
  - 完整显示事情标题、所属主题标签与上下文说明，**不截成单行省略号**。
  - 当存在明确下一步时，主标题优先呈现具体行动（如 **「验收 Atlas 问答的新界面」**），下方注明 `Atlas 问答改造 · 昨天最后确认：已提交代码，界面待验收`。
  - 直接给出四个顺手动作：
    1. **主入口（随证据变化）**：有已保存网页地址显示 **「打开网页 ↗」**；有记录可核对显示 **「看上次记录」**；否则显示 **「看主题」**。
    2. **记下进展**：弹出极简记录框（自动锁定该主题）。
    3. **做完了**：立即从列表收起，底部出现 5 秒 **「已标为做完 · [撤销]」**。
    4. **今天先放下**：移入「已搁置」，不再每天霸占首页；后续有新进展记录时自动唤醒，或随时在记忆里恢复。
- **其余事项保持紧凑单行**：
  - 每行左侧用颜色语义清晰的短标签（`已到期`、`今天到期`、`卡住了`、`还没做`、`推进中`）加所属主题名，正文只写事情本身，悬停同样可直接点「记下进展」「做完了」「先放下」。

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 接着干                                                               │
│ 先处理最上面这一件，下面还有 3 件                                    │
│                                                                      │
│ ┌─ 焦点事项 ───────────────────────────────────────────────────────┐ │
│ │ [还没做]  Atlas 问答改造 · 昨天最后确认                          │ │
│ │ 验收 Atlas 问答的新界面                                          │ │
│ │ 上次已完成改造改动并提交合并请求，界面交互验收尚未完成。         │ │
│ │                                                                  │ │
│ │ [看上次记录]   [记下进展]   [做完了]   [今天先放下]              │ │
│ └──────────────────────────────────────────────────────────────────┘ │
│                                                                      │
│  [卡住了]  Cedar 群组校验 · 2 天前   等待确认伙伴选择上限规则      > │
│  [推进中]  Nova 图表边界  · 昨天     已完成边界用例核对            > │
│  [推进中]  每周阅读笔记   · 3 天前   整理了第三章摘要              > │
│                                                                      │
│ ── 等结果（1）────────────────────────────────────────────────────── │
│  Atlas 发版开关清理 · 11月27日最后确认：已合入主干，当时尚未上线   > │
│                                                                      │
│ ── 整理 ──────────────────────────────────────────────────────────── │
│  昨天有 12 条记录还没有生成回顾                           [生成回顾] │
└──────────────────────────────────────────────────────────────────────┘
```

## 5. 界面二：「记忆 · 主题与主题详情」改动说明

### 5.1 现状问题

1. **弹窗先让人做阅读理解**：一打开就是两段以「记录于某年某月某日」做大标题的长段落，且单条记录里把 `标题：正文` 拼在一起，用户得自己通读才能找出“现在停在哪”；下方「关键记录」展开后又把上面的内容重复一遍。
2. **缺少时间锚点导致过期怀疑**：直接写“线上仍是旧版本”，隔几天再看时用户无法分辨这是实时状态还是几天前的旧快照。
3. **动作层级错位**：「标记完成」是最高频的状态结项动作，却和「管理别名」「记住要求」「整理成报告」混在同一个 `⋯` 菜单里。
4. **已知主题记进展表单过重**：从某个主题里点「记下进展」，仍要面对「主题名称」「回顾分类」「发生时间」等已知或低频字段。

### 5.2 改动方案：按「现在 → 经过 → 动作」只回答三件事

#### （1）第一层：现在（十秒看清最后确认停在哪）
- **标题栏**：展示主题名称（支持页内直接改名，旧名自动存为别名）、所属项目标签，以及一句人话状态（`推进中` / `还没做` / `卡住了` / `先放下` / `已做完`）。
- **最后确认的状态**：明确带上**最后记录的日期锚点**，写清当时确认的事实——例如：**「11 月 27 日最后确认：合并请求已合入主干，当时生产环境仍运行旧版本。」** 即使过了一周再打开，也能准确转述给同事而不会误以为信息失真。
- **下一步 / 还差什么（按需出现）**：
  - 仅当存在用户手写留话、或记录原文明确指出未完项时，才单独展示一行 **「下一步」**（如 *“核对生产环境上线结果”*）。
  - 没有明确依据时直接不显示该行，不编造空话。
- **已有跨日小结时**：最新且有效的主题小结直接作为「现在」的正文概述。

#### （2）第二层：经过（清晰去重的时间脉络，随时核对来源）
- 移除旧版「上方段落 + 下方重复关键记录」的双重展示，统一为按时间倒序的 **「经过」**：
  - 每条记录拆分为：**日期与状态短标签** → **加粗的一句话进展标题**（剥离重复前缀） → **具体说明正文**。
  - 每条记录旁直接附带轻量**来源胶囊**（如 `终端 · 16:40`），平时不占篇幅，有疑问时点一下立刻核对原始截图或文本，也可单条点「更正」。
  - **折叠策略**：已有主题小结或历史记录超过 3 条时，仅展示最近一条变化，其余收进 **「之前的记录（N）」** 默认折叠；无小结且总记录不超过 3 条时直接展开，免去多余点击。
- **浏览容器**：在「记忆 → 主题」宽屏下支持左列表、右详情并排浏览，连续回看多个主题无需反复开关模态框；从「今天」或全局搜索点入时以轻量详情面板打开，看完即回原处。

#### （3）第三层：动作（高频三件套外露，其余收进「整理」）
- **固定高频动作栏**只保留反复使用的三件事：
  1. **记下进展**
  2. **做完了**（若已完成则变为 **恢复跟进**，同样带底部一键撤销）
  3. **继续问**：提供贴合当前主题的追问建议胶囊（如 *“这次改动包含哪些具体内容？”*）与直接输入框；输入问题回车直接发问，不输入点进入则恢复该主题独立会话，不再机械自动发送固定模板问题。
- **「整理」菜单**收纳低频维护项：
  - `给下次留一句 / 设为提醒…`
  - `重新整理小结`
  - `整理成报告…`
  - `记住这个主题的要求…`
  - `其他叫法（管理别名 / 重命名）…`
  - `拆分合并主题`（仅合并组显示）
  - `删除主题（保留原始记录）…`
- **列表右键菜单同步**：主题卡片右键菜单与详情页使用完全一致的词条（`记下进展`、`做完了`、`今天先放下`、`继续问`、`归入项目`）。

```text
┌──────────────────────────────────────────────────────────────────────┐
│ Atlas 发版开关清理                                            ✕      │
│ [推进中] · 归入项目：Atlas 迭代 · 最后确认于 11月27日（昨天）        │
├──────────────────────────────────────────────────────────────────────┤
│ 现在                                                                 │
│ 11 月 27 日最后确认：改动已通过 PR #42 合入主干，当时生产环境仍运行  │
│ 旧版本。                                              [查看来源 (2)] │
│ 下一步：确认生产环境部署结果（来自当日记录）                         │
│                                                                      │
│ 经过                                                                 │
│ ● 11月27日 昨天 · [推进中]                                    [更正] │
│   改动已合入主干，生产环境尚未更新                                   │
│   完成配置项清理并合入主干，等待生产环境发版批次。    [编辑器 16:40] │
│                                                                      │
│ ▸ 之前的记录（1 条：11月22日 提交合并请求）                          │
├──────────────────────────────────────────────────────────────────────┤
│ 推荐追问：[这次合入包含哪些改动？]  [当时为什么保留兼容注释？]       │
│ [记下进展]   [做完了]   [整理 ▾]              [围绕此主题继续问 →]  │
└──────────────────────────────────────────────────────────────────────┘
```

#### （4）已知主题下极简「记下进展」与「给下次的自己留一句」
- 从已有主题或首页条目点 **「记下进展」** 时：
  - **不再展示**「主题名称」输入框与「回顾分类」选择器，发生时间默认当前。
  - 只留两项：**① 状态选择**（`推进中`［默认］ / `还没做` / `卡住了` / `做完了`）；**② 内容输入**（写下这次做了什么、结果怎样，或**给下次的自己留一句“下次从哪开始”**）。
- 当用户在内容里留下明确的下一步（或勾选作为「下次接手提醒」）时，次日打开「今天」会自动将其排在「接着干」首位；验证完顺手补一句结果并点「做完了」，该事项即闭环退场。

## 6. 代码模块映射与不变式核对

### 6.1 涉及文件

| 模块 | 文件 | 职责调整 |
|---|---|---|
| 今日简报投影 | `Sources/RecallKit/Memory/LocalBriefing.swift` | 修正 `openMatters` 优先级排序（紧急度优先于日期）；剥离 `missingReview` 与 `waitingOnOthers`；支持搁置（`dormant`）过滤与结构化字段输出 |
| 主题阅读模型 | `Sources/RecallKit/Memory/MemoryExperience.swift` | `TopicReading` 提炼带日期锚点的「现在」摘要、按证据判定的「下一步」及去重标题前缀的 `TopicTimelineEntry` |
| 主题身份与生命周期 | `Sources/RecallKit/Memory/TopicRegistry.swift`、`TopicListPresentation.swift`、`Storage.swift` | 支持页内改名（旧名转别名）、手动「先放下（`dormant`）」与新进展自动唤醒、手动主题归入项目 |
| 状态动作与撤销 | `Sources/RecallApp/ProductExperienceModel.swift`、`RecallAppModel.swift`、`RecallRootView.swift` | 无确认框即时「做完了 / 先放下」与底部 5 秒一键撤销；限定主题自由提问与原会话恢复 |
| 今日与主题视图 | `Sources/RecallApp/Views/TodayWorkspaceView.swift`、`MatterWorkspaceView.swift` | 落地置顶焦点卡 + 紧凑队列、三段式主题详情、极简记进展面板、「整理」菜单与全站统一词表 |
| 集成验证 | `Verification/TopicListVerification.swift`、`TopicRegistryVerification.swift`、`MemoryExperienceActionVerification.swift` | 覆盖排序优先级、搁置与自动唤醒、改名别名兼容、标题去重及一键撤销 |

### 6.2 不变式与隐私边界检查

1. **用户明确触发**：浏览「今天」与「主题详情」全链路纯本地计算，零隐式模型调用；生成回顾、更新小结、发起追问均仅在用户点击后触发；不后台轮询外部系统或自动打开未确认链接。
2. **敏感数据最小化**：不改变 `recordPageAddress` 默认关闭等隐私默认项；仓库、文档与测试夹具仅使用合成数据。
3. **结果可删除和追溯**：「做完了」「先放下」「改名」「归入项目」均为轻量状态叠加层，不删改原始 `CaptureRecord` 与截图，支持底部即时撤销与记忆页随时恢复；每条结论均可一键展开核对原始来源。

### 6.3 验证与上线观察指标

1. **自动化验证**：运行 `swift build --jobs 1`、`swift run RecallVerifier` 与原生布局预览验证，确保全量集成检查通过。
2. **Mac 交互验收**：在安装完整 Xcode 的 macOS 图形环境中，手动核对悬停操作、焦点卡切换、撤销条动画、窄窗口自适应与深浅色对比度。
3. **五日真实使用观察（产品有效性验收）**：
   - **挑得准不准**：每天首次打开「今天」，置顶第一件事是否确实是当天值得先接手的事，首页噪音（不需要本人跟进却被推上来的事）是否趋近于零。

   - **收尾顺不顺手**：做完或暂缓一件事时，能否在当前界面一次点击完成收尾，不再产生列表堆积感。
