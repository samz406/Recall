## 内容质量

可靠事实优先；具体行动需要对象、动作、本人责任及未完成状态。阅读材料、发布时间、哈希、错误提示和模糊修复提议不等于待办。值得留意必须提供增量信息；不从重复截图推导稳定习惯或从缺少记录推导停滞。保持模型空数组否决与来源核验，不补足栏目。

ProductExperienceVerification 增加八组核心验证，内容组含 60 余种合成边界组合；原有角色归属、模型否决、跨期检索、删除与恢复验证继续运行。不得提交真实截图、真实 OCR 或密钥。

拟定的真实内容精确率目标 95% 需要人工标注抽检，同时报告召回率、样本量及错误归属；本轮合成验证不能证明已经达到该指标。真实模型文本有波动，不能用一次通过替代持续评估。

## Mac 人工验收清单

1. 深浅色、最小窗口、长标题：固定标题与正文不重叠，检查器宽度合适，正文可选择。
2. 读取/整理/保存/成功/部分成功/失败/取消/无记录分别检查；旧结果在生成期间仍可阅读，不能把旧结果标成新结果。
3. 每日回顾指定日期生成、旧版查看、重新生成；无行动/发现不显示栏目。查看依据返回后仍在原回顾。
4. 搜索六类结果，分别打开；日期与来源组合过滤；删除来源后结果消失。
5. 主题合并及撤销、保留全部原文、分类隔离、重新生成受影响回顾；应用重启后保持合并。
6. 每月计划、应用退出补跑、时区及睡眠唤醒；禁用云端与通知后不会继续发送请求或安排通知。
7. 回顾设提醒与重复点击、通知拒绝、完成/取消/推迟、删除来源、恢复记录。
8. 约 6500 条记录、1300 个主题下切换、搜索索引准备、滚动、取消与再生成，记录实际耗时。200ms 可交互框架是目标，尚未实机测量。

运行 `swift build --jobs 1` 与 `swift run RecallVerifier`。本轮运行环境无 macOS 图形会话，不能声称完成窗口、通知和权限的端到端验证。

## 周期回顾精选修复

问题来源：旧管线要求每个候选主题都成文，篇幅只约束单项；失败回退把原始段落直接接入正文，概览又重复前三段。候选数量（例如 173）被误当成真正的事情数量。

现改为：全部材料无损保留 → 去噪、按变化与跨日覆盖构建有界候选 → 可选模型挑重点 → 短正文与独立来源核对 → 同一精选投影用于页面和导出。简洁/适中/详细分别最多 3/5/8 项，单项 120/180/300 字；整体标题、正文、安排分别受 800/1400/2800 字预算约束。没有可信小结可为空，不能用原始 OCR 凑数。材料详情独立入口、搜索、20 组分页，所有来源的删除/更正仍触发旧报告失效。

ReviewDigestVerification 增加六组集成验证：173 个候选、三个篇幅、旧版读取与用户编辑、跨日/类别覆盖、筛选协议和异常 ID、拒绝正文与空选择、禁用云端、来源删除及持久化。真实模型的归纳准确性和 Mac 材料弹窗操作仍需实机抽检；合成验证不代表真实内容已达到某一准确率。
